# speedtest.js — замер скорости скачивания

Консольный скрипт на Node.js: делает 10 последовательных HTTP(S)-запросов к
указанному адресу, каждый раз дочитывает ответ до последнего байта и выводит
среднее время запроса, общий объём скачанных данных и скорость скачивания.

Нужен только **Node.js 18+**. Зависимостей нет, `npm install` не нужен.

## Запуск

```bash
node speedtest.js <адрес>
```

Пример:

```bash
node speedtest.js https://github.com/python/cpython/archive/refs/tags/v3.12.0.tar.gz
```

Можно и через npm: `npm start -- <адрес>`.

Необязательные параметры:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `-n`, `--count` | `10` | сколько запросов сделать |
| `-t`, `--timeout` | `30` | таймаут неактивности в секундах: запрос прерывается, если за это время не пришло ни одного байта. Медленную, но идущую загрузку он не обрывает |
| `-h`, `--help` | — | справка |

## Пример вывода

Реальный прогон с `-n 3`:


## Единицы измерения

Основная единица скорости — **Мбит/с (мегабиты в секунду)**: в ней же
указывают скорость тарифы провайдеров и сервисы вроде Speedtest, поэтому
результат легко сравнить. В скобках дублируется скорость в **МБ/с**
(мегабайты в секунду) — так её показывают браузеры и менеджеры загрузок.

Используются десятичные приставки (SI):

- 1 МБ = 1 000 000 байт
- 1 Мбит/с = 1 000 000 бит в секунду
- 1 МБ/с = 8 Мбит/с

Время — в секундах.

## Как считается

- **Время запроса** — от отправки запроса до получения последнего байта тела
  ответа. Сюда входят DNS, установка соединения и TLS, ожидание ответа сервера
  и сама передача данных. Node переиспользует соединение (keep-alive), если
  сервер это позволяет, поэтому первый запрос обычно чуть медленнее остальных.
- **Среднее время** — сумма времени успешных запросов, делённая на их число.
- **Объём** — сумма байт тела всех успешных ответов (заголовки не считаются).
  Скрипт просит ответ без сжатия (`Accept-Encoding: identity`), так что
  считаются реально переданные байты.
- **Скорость** — общий объём, делённый на суммарное время всех успешных
  запросов. Это честнее, чем среднее арифметическое скоростей отдельных
  запросов: медленный запрос весит столько, сколько он реально длился.
- Чтобы не получать копию из промежуточного кэша, отправляются заголовки
  `Cache-Control: no-cache` и `Pragma: no-cache`. CDN может их проигнорировать.
- Редиректы (301/302 и т. п.) отрабатываются автоматически.

## Ошибки и код выхода

Если запрос завершился ошибкой (HTTP 4xx/5xx, таймаут, нет сети), скрипт
печатает её и переходит к следующему; итог считается по успешным запросам.

Первое нажатие Ctrl+C даёт закончить текущий запрос и печатает итог по уже
выполненным; второе завершает работу сразу.

| Код | Значение |
|---|---|
| `0` | все запросы успешны |
| `1` | ни один запрос не прошёл |
| `2` | часть запросов с ошибкой, либо неверные аргументы |
| `130` | прервано через Ctrl+C |

## Если вы за прокси

Встроенный в Node `fetch` по умолчанию не смотрит на переменные
`HTTP_PROXY` / `HTTPS_PROXY`. Если интернет у вас только через прокси
(ошибки вида `EAI_AGAIN` или `ENOTFOUND`), включите их поддержку
(Node 22.21+ или 24.5+):

```bash
NODE_USE_ENV_PROXY=1 node speedtest.js <адрес>
```

## Советы для точного замера

- Берите файл побольше (от 10–20 МБ): на маленьком файле время уходит в
  основном на установку соединения, и скорость получится заниженной.
- Не запускайте параллельно другие загрузки.
